## Findings

### R10-1 — "Downloaded" is emitted whether or not the md5 was checked

The codebase sets this rule itself. From `app.py`, on the branch that opens an
already-present file:

```python
# downloaded=False: nothing was fetched and no md5 was verified on
# this path, so the status cell must not report "Downloaded and
# opened". "Downloaded" is an integrity claim in this app --
# download_slide checks expected_md5, and local_file only checks
# that the path exists (R07-13).
```

The download path does not hold to it. The worker reports

```python
tcga_dl["msg"] = ("success", f"Downloaded {_path.name}")
```

unconditionally on success, while `_finalize_part` verifies only when it was
given something to verify against:

```python
if expected_md5:
    digest = _md5_of(part)
    ...
```

The md5 comes from `_sel[0].get("md5sum") or <linear scan of the catalog>`. The
first branch is **permanently dead** — `records_to_rows` builds the table rows
from `file_id, file_name, project_id, case_submitter_id, sample_type,
file_size, downloaded` and no md5 (SUMMARY.md open item 6, still latent). So the
catalog scan is the only source, and when it misses, the file is written with a
size check alone and announced with the word the code reserves for an integrity
claim.

**Reachability, stated precisely.** All 50 catalog rows currently carry an md5,
so today the scan always hits and every download really is verified. The defect
is that *nothing enforces that*: a catalog row written before md5 capture, or a
GDC response without the field, downgrades the check silently and the message is
byte-identical either way. A user cannot tell a verified gigabyte from an
unverified one.

*Class: failure — here, absence of a check — rendered as success.*

### R10-2 — QuPath / ASAP annotations still cannot get in (carried from R08-4)

`hescope/importers.py` is complete, tested and unreachable: no control, no CLI
subcommand, no kernel global. Its API is ready to wire —
`parse_geojson_annotations(text)` / `parse_asap_xml(text)` return an
`ImportReport` carrying `.rois`, `.skipped` (reason → count) and `.warnings`,
and `import_annotations(engine, slide_id, report)` writes them through the same
`ROIRepo.add` a drawn ROI uses.

That `skipped`/`warnings` pair is the reason this cannot be a one-line wiring
job: an import that silently keeps 40 of 47 features is this project's most
familiar failure shape. The control has to report what it dropped and why.

### R10-3 — The sidebar's per-ROI View / Delete (carried from R09-4)

R08-2 moved added ROIs into the database, so the ROIs panel's per-row buttons —
built from the session list — no longer render in normal operation. The
capability exists one panel away (Annotations → selectable table that jumps the
viewer and deletes), and the panel now names it, so the user is not stranded.

**Deferred, with the reason.** The Annotations browser carries a documented
constraint: *"THIS CELL MUST NOT REFERENCE get_vp"*, because rebuilding
`mo.ui.table` wipes the row selection and any typed label. Reproducing
View/Delete in the sidebar means per-row buttons keyed by database id and a jump
routed through `ui_actions` rather than a direct `get_vp` read — the same
arrangement the toolbar uses. That is a layout change, and it is not worth
shipping in the same round as an integrity fix.

## Checked and clean — do not re-file

Two audits this round returned nothing, both recorded so a later round does not
repeat them.

* **Every panel's empty / error state is covered.** A mechanical pass over all
  20 `*_view` / `*_panel` cells flagged four (`fallback_view`,
  `hm_progress_view`, `roi_panel`, `tcga_filter_view`); all four are false
  positives of a keyword heuristic. `fallback_view` opens with
  `if _src is None or get_tiles() is not None:`; `tcga_filter_view` guards on
  `tcga_db is not None` and otherwise works off the standalone catalog database;
  `roi_panel`'s `db_roi_rows` is `[]` in DB-free mode, which lands it on the
  plain empty state; `hm_progress_view` is a ticker whose slide read is the
  deliberate publish-time provenance check.
* **The Statistics panel's `elif "stats_table_view" not in dir():` is sound.**
  It looked like it could serve a stale view from a previous run, or let the
  empty state overwrite an error callout. Neither: marimo's
  `_invalidate_cell_state` deletes a cell's defs from kernel state before
  re-running it (`marimo/_runtime/runtime.py:1124`), so `dir()` cannot see the
  previous run's binding, and the error branch is reached only when it set the
  view itself.
* **Two README claims verified rather than assumed.** `extract_features` returns
  exactly **56** values, and the TCGA downloader does thread `expected_md5`
  through to a real `_md5_of` comparison — the defect in R10-1 is about when
  that value is absent, not about the check being missing.
