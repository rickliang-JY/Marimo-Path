## R01-1 — `roi_stats` ignores the ROI shape

**Severity:** high · **Status:** fixed

`hescope/rois.py:108` took a `roi` argument and never referenced it in the
body. All statistics were computed over the bounding-box patch, so every pixel
outside a lasso or circle was silently included. `ROI.mask()` exists for exactly
this and had **no caller in production code** — only in tests.

Reachable from both agent-facing paths: `agent_bridge.py:144` (the
"Send to code agent" submit) and `agent_bridge.py:423` (`selection_stats`, the
zero-click live read). These stats are what lands in the `rois` table and what
the agent consumes.

> **Correction.** The first evidence recorded for this finding was invalid: it
> used a *rectangular* polygon (which fills its own bbox, so no pixel is
> outside it) together with a patch larger than the bbox — a combination
> `extract_patch` never produces. The conclusion held, but the numbers did not
> demonstrate it. Re-done below with a triangle and a patch equal to the bbox,
> which is what the code actually sees.

**Evidence** — a triangle lasso, patch == its bbox, purple inside, brown
outside:

```
bbox: (0, 0, 99, 99)
shape mask covers 51.5% of the bbox

roi_stats(patch)       -> [124.5, 73.9, 91.5]   (bbox-wide: mixes in the brown)
roi_stats(patch, tri)  -> [110.0, 40.0, 140.0]  (fixed)
ground truth inside    -> [110.0, 40.0, 140.0]

H mean bbox-wide : 0.0409
H mean fixed     : 0.0793
H mean truth     : 0.0793
```

Rectangle ROIs were never affected: the patch *is* the bbox.

**Fix.** `ROI.mask()` gained a `scale` parameter (level-0 px per mask px,
default 1.0 so existing callers are unchanged), because `extract_patch` reads
from a downsampled pyramid level and may shrink further for `max_size` —
building a level-0 mask against those pixels would have introduced a fresh
misalignment bug. New `roi_shape_mask()` derives the scale from
bbox size / patch size. `roi_stats` restricts every statistic to tissue ∩ ROI,
and `tissue_fraction` is now measured within the ROI rather than over the bbox.
With `roi=None` the behaviour is byte-identical to before.

**Regression tests:** `tests/test_rois.py::test_roi_stats_respects_roi_shape`,
`::test_roi_stats_mask_scales_to_downsampled_patch`,
`::test_roi_stats_rect_unchanged_by_roi_arg`,
`::test_roi_mask_scale_matches_manual_downsample`.

## R01-2 — `get_latest_selection` raises on a corrupt history line

**Severity:** high · **Status:** fixed

`AGENTS.md` §2 and `agent_bridge.py:213` both promise these tools never raise.
`make_marimo_tool` was the only one of the six with no `try`/`except`, and
`AgentBridge.history()` parsed every line with an unguarded
`ROIPayload.from_json`.

`agent_out/roi_history.jsonl` is append-only and written during "Send to code
agent"; a process killed mid-write leaves a truncated line, after which the
tool failed permanently until the file was repaired by hand.

**Evidence** — one good record followed by a line truncated mid-write:

```
get_latest_selection() -> RAISED JSONDecodeError: Unterminated string starting at: line 1 column 23
annotate_roi (has try/except, for contrast) -> {"error": "RuntimeError: db exploded"}
```

**Fix.** `history()` skips unparseable lines instead of aborting the read, and
`get_latest_selection` is wrapped so any residual failure returns an
`{"error": ...}` JSON string like the DB-backed tools.

**Regression tests:** `tests/test_agent_bridge.py::test_history_skips_corrupt_lines`,
`::test_get_latest_selection_never_raises`.

## R01-3 — Lasso branch of `parse_plotly_selection` is unguarded

**Severity:** high · **Status:** fixed

In `hescope/viewer.py` the box branch explicitly caught
`(TypeError, ValueError, IndexError)`; the lasso branch immediately below it
did not. The asymmetry looks like an oversight. It propagated through
`current_selection` into `get_current_selection()`, breaking the same
never-raise contract as R01-2.

**Evidence:**

```
box   with a null coord -> returned None          (guarded)
lasso with a null coord -> RAISED TypeError: float() argument must be ... not 'NoneType'
lasso non-iterable      -> RAISED TypeError: 'int' object is not iterable
```

**Fix.** The lasso branch guards the same exception set and returns `None`.
`make_live_selection_tool` also wraps its getter, so a failure anywhere
upstream returns `{"error": ...}` rather than propagating.

**Regression tests:** `tests/test_live_selection.py::test_lasso_malformed_returns_none`,
`tests/test_agent_bridge.py::test_get_current_selection_never_raises`.

## R01-4 — TCGA reports success even when opening the slide fails

**Severity:** medium · **Status:** fixed

`app.py:1519` — the download worker thread wrote
`("success", "Downloaded and opened X")` *before* the main thread had attempted
to open anything. The open happens later at `app.py:1560`, at cell top level,
via `_open_slide_path`, whose `open_slide(p)` call was unguarded.

Failure chain: md5 verifies but the file cannot be opened (no backend supports
that SVS variant) → the ticker cell raises → `tcga_status_view` fails to render
for that tick → one second later the ticker re-runs, `open_path` has already
been cleared, so the stale message is consumed and the user sees a green
"Downloaded and opened" with no slide open.

**Fix.** The worker now reports only what it did — `"Downloaded X"` — and the
main thread writes the final message after actually opening: success names the
slide, failure produces a `danger` callout reading
`"Downloaded X, but opening it failed: ..."`. The open and the table refresh
are both wrapped so neither can break the status cell.

**Test coverage: none.** This logic lives in marimo notebook cells, which
cannot be imported and exercised without a running kernel, and faking one to
assert on a message string would test the fake. Verified instead by inspection
plus the `python app.py` full-cell smoke run. Extracting the message
composition into a pure helper in `tcga_panel.py` would make it testable and is
worth doing if this area changes again.

## R01-5 — Deprecated `remove_small_objects(min_size=)`

**Severity:** medium · **Status:** fixed

`remove_small_objects(binary, min_size=...)` is deprecated in scikit-image 0.26
(a `FutureWarning` on every run) and removed in 2.0. The successor is not a
rename: `max_size` removes objects *smaller than or equal to* the threshold and
defaults to 64, where `min_size` removed only those strictly smaller. A naive
rename would silently shift nuclei counts.

> **Scope correction.** The review found only `nuclei.py:79`. Running the suite
> with `-W error::FutureWarning` after the fix exposed **two more call sites**
> the read had missed: `features.py:106` and `qc.py:46`. Reading for a pattern
> is not a substitute for asking the toolchain; later rounds should run the
> suite with deprecation warnings escalated to errors.

**Fix.** One shared `remove_small_objects_strict()` in `nuclei.py`, used by all
three call sites, keeping the strict `area < min_size` boundary and
`ndi.label`'s cross structure (the same 4-connectivity as skimage's
`connectivity=1` default).

**Regression test:** `tests/test_nuclei.py::test_min_size_boundary_is_strict`
pins the strict boundary so it cannot drift.

> **Correction (audit round, 2026-08-10) — the coverage claim is narrower than
> it reads.** `test_min_size_boundary_is_strict` pins the *semantics*
> (`area < min_size`), not the *deprecation*. Reverting `nuclei.py:103` to
> `remove_small_objects(binary, min_size=...)` keeps the strict boundary, so
> that test still passes; only the warnings-as-errors invocation catches it,
> and only while scikit-image still ships the deprecated parameter.
> Measured by restoring the pre-fix call at `nuclei.py:103` (scikit-image
> 0.26.0):
>
> ```
> $ pytest -q tests/test_nuclei.py
> 10 passed, 7 warnings in 1.04s          <-- the bug is BACK and the suite is green
>
> $ pytest -q -W error::FutureWarning tests/test_nuclei.py
> FAILED tests/test_nuclei.py::test_explicit_h_threshold - FutureWarning: Param...
> FAILED tests/test_nuclei.py::test_deterministic - FutureWarning: Parameter `m...
> 7 failed, 3 passed in 1.20s
> ```
>
> So R01-5 is guarded by the **invocation**, not by a test. `pytest -q` alone
> does not protect it. That is why `bugs/README.md` puts
> `-W "error::FutureWarning"` at the top of every round, and it is a reason to
> keep it in whatever runs this suite unattended.

## R01-6 — `read_region` hardcodes `[y, x]` slicing

**Severity:** low · **Status:** fixed

`hescope/slides.py` computes `_y_idx`/`_x_idx` from the series axes string at
`:211-212` and uses them at `:214-219` and `:262-263`, but `:270` sliced
`arr[sy0:sy1, sx0:sx1, :]`, assuming Y and X are axes 0 and 1. Correct for the
common `YXS` layout; wrong for anything that does not lead with Y, X (for
example a planar `SYX`), where the shape lookups and the slicing disagreed.

Latent — not reachable with the slides in the test corpus.

**Fix.** The slice is built from `_y_idx`/`_x_idx`, and the block is transposed
back to `(Y, X, C)` so the rest of the method is unaffected.

**Regression test:** `tests/test_slides.py::test_read_region_respects_axis_order`
reads the same picture from an interleaved `YXS` and a planar `SYX` array and
asserts both return identical pixels.

## R01-7 — `binary_closing` removed in scikit-image 0.28

**Severity:** medium · **Status:** fixed

Found while verifying R01-5, not during the original read. `qc.py:46` called
`skimage.morphology.binary_closing`, deprecated in 0.26 and removed in **0.28**
— a nearer horizon than R01-5's 2.0.

**Fix.** Switched to the documented successor, `skimage.morphology.closing`.
Equivalence on boolean input was verified over 200 randomised masks before
making the change (identical output in every trial), so QC tissue masks do not
shift.

**Regression coverage:** the existing `tests/test_qc.py` suite, which now runs
clean under `-W error::FutureWarning`.

> **Correction (audit round, 2026-08-10) — same caveat as R01-5, stated

## Observations (not bugs)

- **Progress bar goes backwards on download fallback.** When the parallel range
  download fails and `download_slide` falls back to the legacy single stream,
  the progress callback has already been driven up to some byte count and the
  legacy path restarts from 0. Cosmetic only; no byte is double-counted within
  either path.
- **The TCGA ticker never idles.** `mo.ui.refresh(default_interval="1s")` is
  always on, so the status cell re-runs every second and issues a
  `tcga_catalog.stats()` SQLite query even with no download in flight. Cheap,
  and the refresh control is rendered so a user can slow or stop it, but it
  could be gated on `tcga_dl["thread"]` being alive.

## Checked and found clean

- SQLite is safe across the download thread — `SlideCatalog._connect` opens a
  short-lived connection per call rather than reusing one.
- The parallel range download does not double-count on retry: `pos` is
  preserved across attempts and only newly written bytes are aggregated.
- `_finalize_part` verifies size and md5 before an atomic rename, and stale
  `.part` files are restarted rather than resumed.
- `InteractionRepo.record` really is exception-safe, returning `None` on
  failure as documented.
- `compute_grid` wraps the metric callback and writes `NaN` on failure;
  `render_heatmap` blends only non-NaN cells.
- `ml.py` records the encoder in the model meta and reuses the same feature
  path at predict time, avoiding train/inference feature mismatch.
- `current_selection` casts coordinates with `float()`/`int()`, so numpy scalars
  never reach `json.dumps`.

## Lessons for the next round

- **Escalate warnings to errors.** `pytest -W error::FutureWarning` found two
  R01-5 sites and all of R01-7 that a careful read had missed. Run it first,
  not last.
- **Build the evidence out of what the code actually receives.** The first
  R01-1 demonstration used inputs `extract_patch` cannot produce and proved
  nothing, even though the finding was real.
