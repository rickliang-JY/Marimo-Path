## R01-1 — `roi_stats` ignores the ROI shape

**Severity:** high · **Status:** open

`hescope/rois.py:108` takes a `roi` argument and never references it in the
body. All statistics are computed over the bounding-box patch, so every pixel
outside a lasso or circle is silently included. `ROI.mask()` exists for exactly
this and had **no caller in production code** — only in tests.

Reachable from both agent-facing paths: `agent_bridge.py:144` (the
"Send to code agent" submit) and `agent_bridge.py:423` (`selection_stats`, the
zero-click live read). These stats are what lands in the `rois` table and what
the agent consumes.

**Evidence** — a 100x100 patch, purple tissue on the left half, brown on the
right, with a lasso tracing only the left half:

```
reported mean_rgb (whole bbox) : [125.0, 75.0, 90.0]
correct mean_rgb (inside lasso): [110.0, 40.0, 140.0]

reported H mean (whole bbox)   : 0.0397
correct  H mean (inside lasso) : 0.0793      <- 2x off

mask() covers 50% of the bbox -> 50% of the pixels in the stats are OUTSIDE the lasso
```

Rectangle ROIs are unaffected: the patch *is* the bbox.

## R01-2 — `get_latest_selection` raises on a corrupt history line

**Severity:** high · **Status:** open

`AGENTS.md` §2 and `agent_bridge.py:213` both promise these tools never raise.
`make_marimo_tool` was the only one of the six with no `try`/`except`, and
`AgentBridge.history()` parses every line with an unguarded
`ROIPayload.from_json`.

`agent_out/roi_history.jsonl` is append-only and written during "Send to code
agent"; a process killed mid-write leaves a truncated line, after which the
tool fails permanently until the file is repaired by hand.

**Evidence** — one good record followed by a line truncated mid-write:

```
get_latest_selection() -> RAISED JSONDecodeError: Unterminated string starting at: line 1 column 23
annotate_roi (has try/except, for contrast) -> {"error": "RuntimeError: db exploded"}
```

## R01-3 — Lasso branch of `parse_plotly_selection` is unguarded

**Severity:** high · **Status:** open

In `hescope/viewer.py` the box branch explicitly catches
`(TypeError, ValueError, IndexError)`; the lasso branch immediately below it
does not. The asymmetry looks like an oversight. It propagates through
`current_selection` into `get_current_selection()`, breaking the same
never-raise contract as R01-2.

**Evidence:**

```
box   with a null coord -> returned None          (guarded)
lasso with a null coord -> RAISED TypeError: float() argument must be ... not 'NoneType'
lasso non-iterable      -> RAISED TypeError: 'int' object is not iterable
```

## R01-4 — TCGA reports success even when opening the slide fails

**Severity:** medium · **Status:** open

`app.py:1519` — the download worker thread writes
`("success", "Downloaded and opened X")` *before* the main thread has attempted
to open anything. The open happens later at `app.py:1560`, at cell top level,
via `_open_slide_path`, whose `open_slide(p)` call is unguarded.

Failure chain: md5 verifies but the file cannot be opened (no backend supports
that SVS variant) → the ticker cell raises → `tcga_status_view` fails to render
for that tick → one second later the ticker re-runs, `open_path` has already
been cleared, so the stale message is consumed and the user sees a green
"Downloaded and opened" with no slide open.

## R01-5 — Deprecated `remove_small_objects(min_size=)`

**Severity:** medium · **Status:** open

`hescope/nuclei.py:79` calls `remove_small_objects(binary, min_size=...)`,
deprecated in scikit-image 0.26 (a `FutureWarning` on every run) and removed in
2.0. The successor parameter is not a rename: `max_size` removes objects
*smaller than or equal to* the threshold, where `min_size` removed only those
strictly smaller. A naive rename would silently shift nuclei counts.

## R01-6 — `read_region` hardcodes `[y, x]` slicing

**Severity:** low · **Status:** open

`hescope/slides.py` computes `_y_idx`/`_x_idx` from the series axes string at
`:211-212` and uses them at `:214-219` and `:262-263`, but `:270` slices
`arr[sy0:sy1, sx0:sx1, :]`, assuming Y and X are axes 0 and 1. Correct for the
common `YXS` layout; wrong for anything that does not lead with Y, X (for
example a planar `SYX`), where the shape lookups and the slicing would disagree.

Latent — not reachable with the slides in the test corpus.

## Observations (not bugs)

- **Progress bar goes backwards on download fallback.** When the parallel range
  download fails and `download_slide` falls back to the legacy single stream,
  the progress callback has already been driven up to some byte count and the
  legacy path restarts from 0. Cosmetic only; no byte is double-counted within
  either path.
- **The TCGA ticker never idles.** `mo.ui.refresh(default_interval="1s")` is
  always on, so the status cell re-runs every second and issues a
  `tcga_catalog.stats()` SQLite query even with no download in flight. Cheap,
  and the refresh control is rendered so a user can slow or stop it, but it
  could be gated on `tcga_dl["thread"]` being alive.

## Checked and found clean

- SQLite is safe across the download thread — `SlideCatalog._connect` opens a
  short-lived connection per call rather than reusing one.
- The parallel range download does not double-count on retry: `pos` is
  preserved across attempts and only newly written bytes are aggregated.
- `_finalize_part` verifies size and md5 before an atomic rename, and stale
  `.part` files are restarted rather than resumed.
- `InteractionRepo.record` really is exception-safe, returning `None` on
  failure as documented.
- `compute_grid` wraps the metric callback and writes `NaN` on failure;
  `render_heatmap` blends only non-NaN cells.
- `ml.py` records the encoder in the model meta and reuses the same feature
  path at predict time, avoiding train/inference feature mismatch.
- `current_selection` casts coordinates with `float()`/`int()`, so numpy scalars
  never reach `json.dumps`.
